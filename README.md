# Kindergarten Health Monitor

Десктопное приложение для учёта работы медицинского кабинета детского сада:
воспитанники, группы, родители и контакты, медицинские записи, вакцинация,
посещаемость, статистика, отчёты и резервные копии. Все данные хранятся
локально, сетевое взаимодействие не используется.

## Возможности

- **Учёт воспитанников** — личные карточки детей с привязкой к группе, датой
  рождения, информацией об аллергиях и фотографией.
- **Группы** — создание, переименование и удаление групп; фильтрация списка
  воспитанников по группе.
- **Родители и контакты** — ведение списка родителей с телефонами для каждого
  ребёнка.
- **Медицинские записи** — фиксация заболеваний, осмотров и антропометрии
  (рост, вес, ИМТ).
- **Вакцинация** — учёт прививок и автоматическое выявление детей, для которых
  подходит ревакцинация.
- **Посещаемость** — табель присутствия по группам.
- **Статистика** — наглядные диаграммы (matplotlib) по заболеваниям и
  распределению детей по группам.
- **PDF-отчёты** — формирование выписки из медицинской карты ребёнка в PDF.
- **Экспорт в Excel** — выгрузка списка воспитанников в XLSX.
- **Резервные копии** — атомарное резервное копирование базы данных.
- **Фотографии детей** — загрузка и хранение фотографий в отдельном каталоге.

## Стек

- **Python 3.12**
- **Tkinter / ttk** — графический интерфейс
- **SQLite** — локальное хранилище
- **pandas**, **openpyxl** — экспорт в Excel
- **matplotlib** — диаграммы статистики
- **tkcalendar** — выбор дат
- **Pillow** — работа с изображениями
- **reportlab** — генерация PDF

## Структура проекта

- `main.py` — точка входа, графический интерфейс (Tkinter).
- `database.py` — слой данных: SQLite, схема, миграции, резервные копии.
- `paths.py` — централизованные пути ко всем runtime-данным приложения.
- `photos.py` — импорт, хранение и удаление фотографий.
- `charts.py` — построение и освобождение диаграмм статистики.
- `exporters.py` — подготовка данных для экспорта в Excel.
- `reports.py` — генерация PDF-отчётов.
- `populate_db.py` — генератор демо-данных.
- `tests/` — модульные тесты (unittest).
- `KindergartenHealth.spec` — конфигурация PyInstaller для сборки Windows.
- `build.ps1` — скрипт сборки Windows-пакета.

## Быстрый запуск

Требуется установленный Python 3.12. Команды выполняются в PowerShell из
корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

При первом запуске автоматически создаётся чистая база данных в
`.runtime\kindergarten.db`. Демо-данные при этом не добавляются — приложение
открывается с пустой базой.

## Демо-данные

Чтобы заполнить базу синтетическими демонстрационными данными, выполните в
активированном виртуальном окружении:

```powershell
python populate_db.py
```

Эта команда заполняет runtime-базу `.runtime\kindergarten.db`.

Можно явно указать путь к файлу базы данных:

```powershell
python populate_db.py --db C:\path\demo.db
```

После запуска `python main.py` работает с обычной runtime-базой. Демо-данные
генерируются локально и не хранятся в репозитории.

## Runtime data

Все данные, которые приложение создаёт во время работы, находятся в каталоге
`.runtime` и игнорируются Git:

- `.runtime\kindergarten.db` — база данных SQLite;
- `.runtime\photos\` — фотографии детей;
- `.runtime\backups\` — резервные копии.

В упакованной Windows-сборке эти же данные располагаются в каталоге,
доступном для записи текущему пользователю, — `%LOCALAPPDATA%\KindergartenHealth`.
Это реализовано в `paths.py`, который определяет расположение по факту
запуска (исходный код или замороженный пакет).

## Тесты

```powershell
python -m unittest discover -s tests -v
```

Тесты используют только временные файлы и никогда не открывают рабочую базу
данных приложения. Актуальное проверенное состояние: **133 теста проходят,
0 пропущено**.

## Сборка Windows

Установите зависимости разработки (PyInstaller намеренно не входит в
`requirements.txt`):

```powershell
pip install -r requirements-dev.txt
```

Затем выполните либо скрипт сборки:

```powershell
.\build.ps1
```

либо непосредственно команду PyInstaller:

```powershell
python -m PyInstaller KindergartenHealth.spec --noconfirm
```

Готовый исполняемый файл: `dist\KindergartenHealth\KindergartenHealth.exe`
(сборка типа one-dir, оконный режим). Инсталлятор не предусмотрен —
распространяется каталог `dist\KindergartenHealth`. Каталоги `build\` и
`dist\` игнорируются Git.

## Безопасность и данные

- Приложение хранит все данные локально в файле SQLite; сетевое
  взаимодействие и серверная часть отсутствуют.
- База данных, фотографии, резервные копии и экспортируемые файлы могут
  содержать персональные и медицинские сведения о воспитанниках.
- Все runtime-файлы (`.runtime`, базы данных, фотографии, резервные копии,
  PDF, XLSX) исключены из Git через `.gitignore`.
- Не следует коммитить и публиковать реальные медицинские и персональные
  данные.
- Файлы PDF, XLSX и резервные копии SQLite являются обычными файлами в
  открытом виде и должны храниться так же осторожно, как и сама база.
- Локальное десктопное приложение не реализует аутентификацию — любой,
  имеющий доступ к файлам пользователя, имеет доступ к данным.

## Архитектурные особенности

- **Версионирование схемы** через `PRAGMA user_version` и фреймворк прямых
  миграций: приложение не выполняет деструктивных действий при обновлении
  базы данных.
- **Атомарное резервное копирование**: копия создаётся во временный файл с
  последующей заменой целевого, поэтому сбой посередине не портит
  существующую резервную копию.
- **Управляемый жизненный цикл фотографий**: файлы хранятся в выделенном
  каталоге, удаляются только внутри него и не дублируются при обновлении.
- **Безопасный экспорт в Excel**: текстовые значения экранируются от
  формульных инъекций, идентификаторы остаются числами.
- **Централизованные runtime-пути**: все записи приложения направляются в
  один игнорируемый Git каталог.

## Ограничения

- Локальное десктопное приложение; работа без сети и серверной части.
- Не реализована встроенная аутентификация пользователей.
- Логика напоминаний о вакцинации (учёт отказов и медотводов, различение
  первичной вакцинации и ревакцинации) намеренно консервативна и должна быть
  подтверждена профильным специалистом перед использованием в реальной
  медицинской практике.
